# 考场策略与检查清单

## 一、开局 5 分钟

1. 通读全部题目，给每道题标难度（易 / 中 / 难）。
2. 先做**填空题**：通常暴力或数学就能出答案，性价比最高。
3. 再按「易 → 中 → 难」顺序做，不要卡在一道题上超过 40 分钟。

## 二、OI 赛制的得分策略

- **先交暴力，再想优化**：能过 3 个测试点就先交，保证不空题。
- 不会的题也要写：读入 + 输出样例/特判，有时能骗到 0~10 分。
- 大数据过不了就用小数据范围交，别让数组开太大导致全部 RE。
- 每道题至少留一次提交机会，避免最后网络拥堵。

## 三、时间分配（4 小时参考）

| 阶段 | 时间 | 内容 |
|---|---|---|
| 读题 | 10 min | 全部题目过一遍，标难度 |
| 第一轮 | 90 min | 填空 + 简单题 |
| 第二轮 | 100 min | 中等题，先暴力后优化 |
| 第三轮 | 30 min | 回头啃难题，拿部分分 |
| 检查 | 10 min | 见下方清单 |

## 四、提交前检查清单

- [ ] 主类名是 `Main`，没有 `package` 语句
- [ ] 数组开得够大（多开 5~10 个，1-indexed 时开 n+1）
- [ ] 乘积 / 累加会不会爆 `int`，有没有转 `long`
- [ ] 多组输入是否读到 EOF（`while (in.next() != null)`）
- [ ] 输出格式：大小写、换行、空格、保留小数位
- [ ] 递归深度是否可能栈溢出（DFS 深度 > 10^4 改用 BFS 或手动栈）
- [ ] 取模题是否每步都取模，负数取模要 `(x % MOD + MOD) % MOD`
- [ ] 图论题是有向还是无向，边要不要存两次
- [ ] 二分边界：`while (l < r)` 还是 `while (l <= r)`，会不会死循环
- [ ] `HashMap` 的 key 用 `Integer`/`String`，不要用数组

## 五、高频翻车点

| 坑 | 后果 | 规避 |
|---|---|---|
| `int` 溢出 | 答案变负数 | 用 `long`，乘之前先转 |
| 数组越界 | RE 全挂 | 边界判断，多开空间 |
| 死循环 | TLE | 二分、BFS visited 检查 |
| 忘记清空多组数据 | WA | 每组重新 new 或 `Arrays.fill` |
| `String` 用 `==` 比较 | WA | 一律用 `equals` |
| `Stack` / `LinkedList` 当栈 | 慢 | 用 `ArrayDeque` |
| 频繁 `System.out.println` | TLE | 用 `StringBuilder` 汇总 |
| 递归 + 大数组 | StackOverflow | 改迭代或加 `-Xss`（考场不一定能设） |

## 六、卡题时的处理

1. 先写暴力对拍小数据，确认理解没错。
2. 换思路：能不能二分答案？能不能反过来枚举？能不能用前缀和？
3. 还是不会：写特判 + 样例，交上去拿部分分，去做下一题。
4. 最后 20 分钟不要再开新题，集中检查已提交的代码。

## 七、心态

- 省赛 B 组大部分人是「会做 4~6 题」，稳住简单题就赢一半。
- 遇到完全没思路的题很正常，先保证会做的题不丢分。
- 交卷前把每道题的代码重新扫一遍，比多想一道题更划算。
