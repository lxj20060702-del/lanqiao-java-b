# AI 评分指南

> 目标：写完代码 30 秒内拿到「能得多少分 + 错在哪 + 怎么改」，不用等 OJ。

## 一、100 分量表

| 维度 | 分值 | 评分要点 |
|---|---|---|
| 正确性 | 40 | 样例是否通过；边界（n=1、全相同、最大值）是否正确；逻辑是否有反例 |
| 复杂度与得分能力 | 25 | 是否满足数据范围；预估能过多少测试点；能否在时限内跑完 |
| 思路表达 | 15 | 能否说清「为什么这样做」；暴力→优化的推导是否合理 |
| 代码质量 | 10 | 变量命名、结构清晰、有无重复代码、是否可直接提交 |
| 鲁棒性 | 10 | 溢出（int/long）、数组越界、空输入、多组数据初始化、取模负数 |

## 二、分数对照

| 分数 | 含义 | 下一步 |
|---|---|---|
| 90~100 | 可 AC | 看能否再优化常数，然后做下一题 |
| 75~89 | 大部分测试点能过 | 补边界与溢出，重测极端数据 |
| 60~74 | 只有暴力分 | 对照本章解法演进，重写优化版 |
| 40~59 | 思路对但实现有错 | 先手算 2 组小数据调试 |
| < 40 | 题意或算法理解有误 | 回本章重读概念与识别部分 |

## 三、通用评分提示词（直接复制）

把下面整段发给任意 AI，替换三个占位内容即可。

````text
你是一位蓝桥杯 Java 大学 B 组教练。请严格评分，不要为了鼓励而放水。

【题目】
{{粘贴完整题目，包含输入输出格式和样例}}

【数据范围】
{{粘贴 n、m、值域、时间限制}}

【我的思路】
{{用 2~5 句话说明你的算法}}

【我的代码】
```java
{{粘贴代码}}
```

请按以下流程评分：
1. 先用一句话复述题意，确认你没有理解偏。
2. 逐行检查代码，指出会导致 WA / RE / TLE 的具体问题，并给出反例输入。
3. 用给定样例手动模拟，说明输出是否正确。
4. 按 100 分制打分，必须给出每个维度的分数：
   - 正确性 40 分
   - 复杂度与得分能力 25 分（结合数据范围，估算能过多少测试点）
   - 思路表达 15 分
   - 代码质量 10 分
   - 鲁棒性 10 分
5. 给出 3 条最优先的改进建议，按收益排序。
6. 给出修改后的完整 Java 代码（类名 Main，不要 package）。
7. 最后给出这道题在蓝桥杯中的「预期得分区间」，例如 60~70 分。

要求：
- 如果代码有错，必须给出一个能让它出错的具体输入。
- 如果无法确定正确性，请明确说「不确定」，不要编造。
- 不要只夸优点，至少指出一个缺点。
````

## 四、手机上的使用方式

1. 在 GitHub App 里打开对应题型，复制「小试牛刀」的题目和你的代码。
2. 打开任意 AI 对话，粘贴上面的提示词并替换占位内容。
3. 把返回的分数和错因记到 `problems/` 或考点清单里。

## 五、评分示例（节选）

```text
总分：78 / 100
- 正确性 30/40：样例通过，但 n=1 时数组越界
- 复杂度 22/25：O(n log n)，可以通过 10^5
- 思路 13/15：二分答案方向正确
- 代码质量 8/10：变量名可读
- 鲁棒性 5/10：未用 long，乘积会溢出

反例：输入 "1 1000000000"，你的程序输出负数。
优先改进：1) 乘积转 long  2) 补 n=1 边界  3) 二分上界用最大值而非 1e9
预期得分：70~80 分
```

## 六、注意事项

- AI 评分的价值在**发现问题和给改进方向**，最终以 OJ 评测为准。
- 同一份代码可以让两个不同 AI 各评一次，交叉验证。
- 不要直接把 AI 改好的代码抄进仓库，先自己重写一遍，再对比。
- 评分前先自己跑一遍样例，避免让 AI 替你调试低级错误。
