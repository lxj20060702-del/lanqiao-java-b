# 题型 02 · 排序与贪心

> 一句话：**排序是预处理，贪心是每一步都选当前看起来最好的，并且能证明它不后悔。**

## 1. 概念：这个题型在考什么

- 贪心：把问题拆成一系列选择，每一步选局部最优，期望全局最优。
- 排序：让「局部最优」变得容易取到，所以贪心题几乎都要先排序。
- 为什么有效：需要证明——常用**交换论证**（如果最优解和贪心选择不同，交换后不会更差）或**反例排除**。
- 省赛地位：区间调度、分配、合并、排队类题目，代码短、得分快。

**贪心的风险**：看起来很对但其实是错的。写完必须问自己：能不能举出一个反例？

## 2. 如何识别

| 题面特征 | 判断 |
|---|---|
| 求最大数量 / 最小代价 / 最大收益 | 贪心候选 |
| 有「选择若干个，互不冲突」 | 排序 + 贪心 |
| 每次合并 / 取最小的两个 | 优先队列 + 贪心 |
| 分配任务、排队使总等待最小 | 排序 + 贪心 |
| 需要证明「不会更差」 | 交换论证 |

数据范围信号：n ≤ 10^5 且要求 O(n log n)，通常是「排序 + 一次扫描」。

## 3. 从低分到满分

**例题**：有 n 个活动，每个活动有开始时间和结束时间，一个人最多能参加多少个互不重叠的活动？

### 3.1 暴力枚举子集（小数据能过）

枚举所有子集，判断是否两两不重叠，取最大大小。

```java
int best = 0;
for (int mask = 0; mask < (1 << n); mask++) {
    // 检查 mask 中的活动是否两两不重叠
    // 合法则 best = Math.max(best, Integer.bitCount(mask));
}
```

- 复杂度 O(2^n · n)，n ≤ 20 才能跑。
- 只能拿 n 很小的测试点。

### 3.2 满分解法：按结束时间排序 + 贪心

直觉：越早结束，给后面留的时间越多。

```java
Arrays.sort(a, (x, y) -> Integer.compare(x[1], y[1]));   // 按结束时间升序
int cnt = 0, lastEnd = Integer.MIN_VALUE;
for (int[] e : a) {
    if (e[0] >= lastEnd) {      // 与上一个不重叠
        cnt++;
        lastEnd = e[1];
    }
}
```

- 复杂度 O(n log n)。
- 正确性：假设最优解第一个活动不是最早结束的，用贪心选的那个替换它，剩余空间只会更大，不会变差。

| 解法 | 复杂度 | 得分 |
|---|---|---|
| 枚举子集 | O(2^n · n) | n ≤ 20 |
| 排序 + 贪心 | O(n log n) | 满分 |

## 4. 贪心题通用流程

```java
// 1. 确定排序关键字（结束时间？价值？比率？）
Arrays.sort(a, (x, y) -> Integer.compare(x.key, y.key));
// 2. 一次扫描，能选就选
long ans = 0;
for (int[] e : a) {
    if (可以选) {
        选它;
        ans += 收益;
    }
}
```

排序关键字选错是贪心最常见的错误。写完先举 3 组小数据验证。

## 5. 小试牛刀

### 练习 1 · 排队接水（易）

n 个人排队接水，第 i 个人接水需要 `t[i]` 分钟。一个人接水时，后面所有人都要等待。安排顺序使所有人的**等待时间之和**最小。

**输入**：第一行 n（1 ≤ n ≤ 10^5），第二行 n 个整数 t[i]

**输出**：最小的等待时间之和

**样例**

```text
输入：
3
3 1 2
输出：4
```

解释：按 1、2、3 分钟的顺序，等待时间为 0 + 1 + 3 = 4。

<details>
<summary>参考答案</summary>

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        int[] t = new int[n];
        for (int i = 0; i < n; i++) t[i] = sc.nextInt();
        Arrays.sort(t);                       // 接水时间短的先来
        long sum = 0;
        for (int i = 0; i < n; i++) {
            sum += (long) t[i] * (n - 1 - i); // 第 i 个人会被后面 n-1-i 个人等待
        }
        System.out.println(sum);
    }
}
```

复杂度 O(n log n)。

</details>

**满分要点**：升序排序；用 long；理解「每个人被等待的次数」。
**常见失分**：算成接水时间总和；用 int 溢出（n = 10^5 时总和可达 10^15）。

### 练习 2 · 合并果子（中）

有 n 堆果子，每次只能合并两堆，消耗的体力等于两堆重量之和。合并到只剩一堆，求最小总体力。

**输入**：第一行 n（1 ≤ n ≤ 10^5），第二行 n 个整数表示每堆重量

**输出**：最小总体力

**样例**

```text
输入：
3
1 2 9
输出：15
```

解释：先合并 1 + 2 = 3（消耗 3），再合并 3 + 9 = 12（消耗 12），总计 15。

<details>
<summary>参考答案</summary>

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt();
        PriorityQueue<Long> pq = new PriorityQueue<>();
        for (int i = 0; i < n; i++) pq.offer(sc.nextLong());
        long cost = 0;
        while (pq.size() > 1) {
            long merged = pq.poll() + pq.poll();  // 每次取最小的两堆
            cost += merged;
            pq.offer(merged);
        }
        System.out.println(cost);
    }
}
```

复杂度 O(n log n)。

</details>

**满分要点**：小根堆；每次取两个最小；合并后放回；long。
**常见失分**：用 `PriorityQueue` 默认小根堆却写成大根堆；每次只取一个；n = 1 时输出 0。

## 6. AI 评分要点

- **排序关键字是否正确**：结束时间、开始时间、单价、时间长度，选错直接 WA。
- 有没有反例？让 AI 尝试构造一组让贪心失效的输入。
- 比较器是否用了 `Integer.compare`（直接相减会溢出）。
- 总和、代价是否用 long。
- 优先队列是否真的需要（有些题排序后一次扫描即可）。
